Three questions we cannot answer

What settings?

model.joblib is 1.3 KB of pickled model. Which hyperparameters produced it? Nothing in the file says.

How good was it?

Someone printed an accuracy in a notebook cell. The output has since been cleared. The number is gone.

Was the next one better?

You trained forty variations that week. Only the last one survives on disk — and it may not have been the best.

Every one of these is the same missing thing: nothing recorded the run. That is precisely the hole MLflow fills.

WHYWhy we use MLflow

Three reasons, and the honest one first: you forget.

Reason 1 — you lose the runs you did not record

Two weeks into a project you have run training sixty-odd times. Ask yourself which learning rate produced the 0.91 from last Thursday, on which split, with which feature set.

MLflow's real product is not the UI — it is the fact that logging is cheaper than remembering. Three lines at write time beats an afternoon of archaeology later.

Reason 2 — the comparison table builds itself

Every run is a row; every param and metric is a column. Sort by your metric, tick two rows to diff them, click one to get its artifacts, model and tags.

And it is queryable: mlflow.search_runs() hands you the same table as a pandas DataFrame — so "pick the best model and register it" becomes code, not a human reading a spreadsheet.

Reason 3 — a metric over time, not one number at the end

for epoch in range(40):
    loss = train_one_epoch()
    mlflow.log_metric("val_loss", loss, step=epoch)   # same name, many steps

One extra argument turns a printed number into a curve you can overlay across runs — the difference between "it got worse" and "it started overfitting at epoch 12".

Reason 4 — the model outlives the notebook that made it

joblib.dump

  • Just the fitted object.
  • Breaks silently when sklearn is upgraded.
  • No record of the input columns or their types.
  • Loading needs the original class importable.

mlflow.*.log_model

  • Model + requirements.txt + conda env.
  • An input signature, enforced at predict time.
  • An input example stored alongside it.
  • Loadable as pyfunc — no training code needed.
  • Servable: mlflow models serve -m runs:/<id>/model.

The test that matters: can a colleague load your model next year, on a fresh machine, without reading your training script? Pickle says no. MLflow says yes.

When not to reach for MLflow

One model, trained once, never revisitednothingTracking overhead with no payoff

MLflow is deliberately small. That is why it drops into an existing codebase in an afternoon.

PART 02MLflow

The lab notebook that fills itself in — every run, every parameter, every score.

What MLflow is

A Python library plus a local web UI that records what happened during training. Add three lines to your script and never keep a results spreadsheet again.

1 · Tracking

Log params, metrics, files, per run. This is 80% of what people use. Comes with a UI.

2 · Models

A standard folder format for a saved model + its dependencies, loadable by anything.

3 · Model Registry

Named, versioned models with stages: Staging → Production → Archived.

4 · Projects

A packaging convention so mlflow run . works on anyone's machine.

The four words you must know

WordMeansExample
ExperimentA named project folder for runs"churn-model"
RunOne execution of your training codethe 3pm attempt with 200 trees
ParamAn input you chose, logged oncen_estimators=200
MetricA number that came out; can be logged repeatedlyaccuracy=0.87, loss per epoch
ArtifactAny file the run producedthe model, a PNG, a CSV

Rule of thumb: if you chose it, it's a param. If you measured it, it's a metric. If it's a file, it's an artifact.

Your first tracked run

pip install mlflow

import mlflow

mlflow.set_experiment("churn-model")        # create-or-reuse a bucket of runs

with mlflow.start_run(run_name="rf-baseline"):
    mlflow.log_param("n_estimators", 200)     # an input I chose
    mlflow.log_param("max_depth", 5)

    model.fit(X_train, y_train)
    acc = model.score(X_test, y_test)

    mlflow.log_metric("accuracy", acc)        # a number I measured
    mlflow.log_artifact("confusion.png")      # any file worth keeping

Everything lands in an mlruns/ folder next to your script. No server, no signup, no cloud.

Autolog: the lazy way

import mlflow
mlflow.sklearn.autolog()      # or mlflow.pytorch / tensorflow / xgboost / lightgbm

model.fit(X_train, y_train)   # that is it. really.

MLflow patches the library and automatically records:

  • every hyperparameter you passed to the estimator,
  • the training metrics it can compute,
  • the fitted model itself, as an artifact,
  • a signature describing the expected input columns.

The trade-off: autolog logs a lot, and names things its own way. Great for exploring, worth replacing with explicit log_param calls once the project is serious.

The UI

mlflow ui                       # serves http://127.0.0.1:5000
mlflow ui --port 5001 --host 0.0.0.0

What you get

  • A sortable table: one row per run, one column per param/metric.
  • Tick two runs → Compare → side-by-side diff and scatter plots.
  • Click a run → its artifacts, model, tags, source file, git commit.

Where the data lives

  • Default: the local mlruns/ folder.
  • Team setup: --backend-store-uri postgresql://… plus --default-artifact-root s3://….
  • Point a script at a server with mlflow.set_tracking_uri("http://…").

Start local. Move to a shared server only when a second person needs to see your runs.

Saving and re-loading a model

with mlflow.start_run() as run:
    info = mlflow.sklearn.log_model(model, name="model",
                                    input_example=X_test[:5])   # records the schema
    run_id = run.info.run_id

# later, anywhere, no import of your training code needed:
# MLflow 3: use the URI it handed back -- models:/<model_id>
loaded = mlflow.sklearn.load_model(info.model_uri)
# still valid, and what older tutorials show:
loaded = mlflow.sklearn.load_model(f"runs:/{run_id}/model")
loaded.predict(X_new)

# framework-agnostic flavour — works for any logged model:
loaded = mlflow.pyfunc.load_model(f"runs:/{run_id}/model")

Why not just pickle.dump? MLflow stores the model and its conda/pip environment and its input schema — so it still loads on another machine, next year.

Model Registry: from "a run" to "the model"

mlflow.register_model(f"runs:/{run_id}/model", "churn-classifier")
Created version '3' of model 'churn-classifier'.

from mlflow import MlflowClient
c = MlflowClient()
c.set_registered_model_alias("churn-classifier", "champion", 3)   # current API

# serving code never mentions a run id again:
model = mlflow.pyfunc.load_model("models:/churn-classifier@champion")
  • Every promotion is recorded: who, when, from which run.
  • Rolling back is re-pointing the alias, not a redeploy scramble.

Older tutorials use transition_model_version_stage(... "Production") — stages are deprecated in MLflow 2.9+ in favour of aliases.

How MLflow is wired

Example: before and after MLflow

Before

import joblib

n_est = 200
model = RandomForestClassifier(
            n_estimators=n_est).fit(X, y)
acc = model.score(Xt, yt)

print(acc)                # scrolls away

    f"model_{acc:.3f}.pkl")  # 40 files later…

# and forget which split you used

After

import mlflow
mlflow.set_experiment("churn")

with mlflow.start_run():
    mlflow.log_param("n_estimators", 200)
    model = RandomForestClassifier(
                n_estimators=200).fit(X, y)

    mlflow.log_metric("accuracy", acc)
    mlflow.sklearn.log_model(model, name="model")

+5 lines and every run is permanently searchable, comparable and re-loadable.

Example: a hyperparameter sweep worth keeping

import mlflow, itertools
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import roc_auc_score

mlflow.set_experiment("churn-sweep")

for n_est, depth in itertools.product([25, 60, 150, 300], [3, 8]):
    with mlflow.start_run(run_name=f"rf-{n_est}-d{depth}"):
        p = {"n_estimators": n_est, "max_depth": depth, "random_state": 42}
        mlflow.log_params(p)                              # plural: one dict

        m = RandomForestClassifier(**p).fit(X_train, y_train)
        auc = roc_auc_score(y_test, m.predict_proba(X_test)[:, 1])

        mlflow.log_metrics({"roc_auc": auc})
        mlflow.set_tag("model_family", "random_forest")      # free-form label

# 8 runs. Now ask which one won — no spreadsheet involved:
best = mlflow.search_runs(experiment_names=["churn-sweep"],
                          order_by=["metrics.roc_auc DESC"]).iloc[0]
print(best["params.n_estimators"], best["metrics.roc_auc"])
300  0.9241

This is the moment people convert. Eight runs, zero bookkeeping, and the table is queryable from Python and browsable in the UI.

Datasets — telling MLflow which data

A run with params and metrics but no record of its input data is only half a record. MLflow tracks datasets as first-class objects.

import mlflow, pandas as pd

df = pd.read_csv("data/train.csv")

ds = mlflow.data.from_pandas(df,
        source="data/train.csv",       # where it came from (file, URL, S3, table)
        name="churn-train",           # a human name
        targets="churn")              # which column is the label

with mlflow.start_run():
    mlflow.log_input(ds, context="training")     # also: "validation", "eval"
    ...

What gets stored

  • digest — a hash of the data, so two runs on identical data match
  • source — the path/URI it was loaded from
  • schema — columns and dtypes
  • profile — row count and basic stats

Other constructors

mlflow.data.from_numpy(arr)
mlflow.data.from_spark(sdf)
mlflow.data.from_huggingface(hf_ds)

Read it back from a run with run.inputs.dataset_inputs.

The honest limit: MLflow stores the dataset's fingerprint and address, not the bytes. If the file at that path is overwritten, the digest no longer matches — which is the signal that the data moved under you.

MLflow 3 — models became first-class

Until MLflow 2, a model was a folder inside a run. In MLflow 3 a LoggedModel is its own entity with its own id, and this changes the code you will see in tutorials.

MLflow 2 style (still works)

with mlflow.start_run() as r:
    mlflow.sklearn.log_model(
        model, artifact_path="model")

m = mlflow.sklearn.load_model(
        f"runs:/{r.info.run_id}/model")

MLflow 3 style

info = mlflow.sklearn.log_model(
        model, name="model")    # no run needed

m = mlflow.sklearn.load_model(info.model_uri)
# -> models:/<model_id>

# and models are searchable in their own right
mlflow.search_logged_models(experiment_ids=["0"],
                            filter_string="metrics.roc_auc > 0.9")

# artifacts also moved on disk:
#   2.x  experiments/<exp>/<run_id>/artifacts/model/
#   3.x  experiments/<exp>/models/<model_id>/artifacts/

Write code that survives both: take the URI MLflow hands back (info.model_uri) instead of assembling "runs:/" + id + "/model" yourself.

Advanced 1 — nested runs

A sweep or a cross-validation is one logical experiment made of many trainings. Nested runs give you a parent row that collapses its children in the UI.

with mlflow.start_run(run_name="grid-search") as parent:
    mlflow.log_param("search_space", "n_estimators x max_depth")

    for n in [50, 100, 200]:
        with mlflow.start_run(run_name=f"n={n}", nested=True):   # child
            mlflow.log_param("n_estimators", n)
            mlflow.log_metric("roc_auc", fit_and_score(n))

    mlflow.log_metric("best_roc_auc", best)      # summary on the parent

Same trick for CV folds: parent = the model config, children = fold 1..k, parent logs the mean and std.

Advanced 2 — ship preprocessing with the model

The classic production bug: the model expects scaled features, the serving code sends raw ones. Fix it by making the whole pipeline the model.

# option A: an sklearn Pipeline is already one object
from sklearn.pipeline import Pipeline
pipe = Pipeline([("scale", StandardScaler()), ("clf", RandomForestClassifier())])
mlflow.sklearn.log_model(pipe, name="model")

# option B: arbitrary Python around any model
class ChurnModel(mlflow.pyfunc.PythonModel):
    def load_context(self, context):
        self.m = joblib.load(context.artifacts["clf"])

    def predict(self, context, model_input, params=None):
        X = clean(model_input)                     # your own feature code
        return self.m.predict_proba(X)[:, 1]

mlflow.pyfunc.log_model(name="model", python_model=ChurnModel(),
                        artifacts={"clf": "models/model.pkl"},
                        pip_requirements=["scikit-learn==1.5.2", "pandas"])

Now serving is dumb on purpose: it hands over raw rows and gets probabilities back.

Advanced 6 — the GenAI side

MLflow 3 tracks LLM applications, not just classifiers. Same vocabulary, new object: a trace.

Autolog — the full picture

mlflow.autolog()          # every supported library you have imported

# or one at a time, with control:
mlflow.sklearn.autolog(
    log_models=True,             # log the fitted model as an artifact
    log_input_examples=False,    # store a sample of the training input
    log_model_signatures=True,   # infer and store the schema
    log_datasets=True,           # record the training dataset
    exclusive=False,            # True = skip runs you created yourself
    silent=False,               # True = suppress its warnings
    extra_tags={"team": "risk"},  # tag every autologged run
    disable=False)

System metrics — was it the model or the machine?

pip install psutil          # required
pip install pynvml          # NVIDIA GPUs (pyrsmi for AMD)

mlflow.enable_system_metrics_logging()      # for every run in this process
# or, globally, without touching the code:
#   export MLFLOW_ENABLE_SYSTEM_METRICS_LOGGING=true

Every run then carries a second family of metrics, sampled over time and prefixed system/:

system/cpu_utilization_percentage      system/gpu_utilization_percentage
system/system_memory_usage_megabytes   system/gpu_memory_usage_megabytes
system/disk_usage_megabytes            system/gpu_power_usage_watts
system/network_receive_megabytes       system/disk_available_megabytes

Why it earns its slide: "the GPU sat at 8% for four hours" is a different bug from "the model underfits", and without this you cannot tell them apart after the fact.

Searching runs, and the store that makes it possible

mlflow.search_runs(
    experiment_names=["churn-model"],
    filter_string="metrics.roc_auc > 0.9 "
                  "and params.max_depth = '8' "      # params are STRINGS
                  "and tags.team = 'risk'",
    order_by=["metrics.roc_auc DESC", "start_time DESC"],
    max_results=50)

The gotcha

  • Metrics compare numerically; params and tags are strings — quote them.
  • attributes.status = 'FINISHED', attributes.run_name also work.
  • Same syntax in the UI search box.

Why we used SQLite, not the default folder

The file store (./mlruns) cannot host the Model Registry — registration needs a database-backed store. One line makes it work:

mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow doctor                 # environment report
mlflow gc                     # permanently delete runs marked deleted
mlflow server --serve-artifacts --host 0.0.0.0    # proxy artifacts through the server
export MLFLOW_TRACKING_USERNAME=... MLFLOW_TRACKING_PASSWORD=...

Start tomorrow, in this order
